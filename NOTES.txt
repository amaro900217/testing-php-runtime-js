# PHP WASM Runtime in the Browser

Run PHP code directly in the browser using WebAssembly (php-wasm). This library provides support for inline code execution and simulates a complete HTTP request cycle, all while being optimized for a non-blocking startup after the first initialization.

## Installation

Your PHP application files should be placed inside a zip archive located at `assets/www/php_api.zip`. This library will automatically unzip, persist in browser and run the files upon requests.

```html
<!-- Load the library -->
<script src="php-runtime.js" type="module"></script>

<!-- Configure the PHP Runtime -->
<script type="module">
  await runPHP.init({
    DEBUG: true,
    NUM_WORKERS: 2
    // ...
  });
</script>
```

## Usage

### Execute Inline PHP Code
```html
<script>
  const result = await runPHP.inline('<?php echo "Hello from PHP!"; ?>');
  console.log(result);
</script>
```

### Make an HTTP-Like Request
```html
<script>
  const result = await runPHP.request({
      method: "GET", // POST
      query: "/www/index.php?user=test", // "/www/api/endpoint"
      payload: "otheruser=theuser&value=123", // ""
      headers: "Content-Type:application/x-www-form-urlencoded;" // ""
  });
  console.log(result);
</script>
```

## Configuration

| Option          | Description                    | Default             |
|-----------------|--------------------------------|---------------------|
| DEBUG           | Enable detailed logging        | `false`             |
| NUM_WORKERS     | Number of concurrent workers   | `2`                 |
| TIMEOUT_WORKER  | Timeout for each worker        | `1000`              |
| DOCUMENT_ROOT   | PHP document root              | `/www`              |
| ENTRY_POINT     | Default PHP script             | `""`                |
| SERVER_ADDR     | Virtual server IP              | `127.0.0.1`         |
| SERVER_NAME     | Server name                    | `browser-localhost` |
| SERVER_PORT     | Server port                    | `8080`              |
| SERVER_SOFTWARE | Server version                 | `wasm-server-0.0.8` |

## Features

- **Server-less PHP Execution:** Run a PHP application in the browser without needing a backend.
- **Non-Blocking Initialization:** The heavy initial setup process runs in a background worker.
- **Concurrent Request Handling:** It can use multiple Web Workers to handle several PHP requests in parallel.
- **Persistent Caching:** Caches the core WASM binary and the entire PHP application filesystem in IndexedDB for faster subsequent page loads.
- **Full HTTP Environment Simulation:** Simulates `$_SERVER`, `$_GET`, `$_POST`, and other PHP superglobals.
- **Securely Sandboxed:** The PHP environment is completely isolated from the host system.

```
       │
       ▼
[Primary Worker: Install WASM + PHP Project]
       │
       ▼
[Check installation: Check installation and Initialize a Warm up Worker]
       │
       ▼
[Worker Pool: Load WASM, Ready for Requests] ◄─────────────────┐
       │                                                       │
       ├────────────► [runPHP.inline(code)]                    │
       │                      │                                │
       │                      ▼                                │
       │              [Assign Inline Code to Worker]           │
       │                      │                                │
       │                      ▼                                │
       │              [Worker Execution]                       │
       │                      │                                │
       │                      ├─ Run PHP Code in WASM          │
       │                      └─ Capture Output                │
       │                      │                                │
       │                      ▼                                │
       │              *[Return Result to Main Thread]* ───────►│
       ▼                                                       │
[runPHP.request({method, query, payload, headers})]            │
       │                                                       │
       ▼                                                       │
[Request Queue → Assign to Available Worker]                   │
       │                                                       │
       ▼                                                       │
[Worker Execution]                                             │
       │                                                       │
       ├─ Build PHP Environment (Server + GET/POST + Headers)  │
       ├─ Run PHP Code in WASM                                 │
       └─ Capture Output                                       │
       │                                                       │
       ▼                                                       │
*[Return Result to Main Thread]* ──────────────────────────────┘
```

## Code Review Analysis

### Architecture Overview
- Main runtime (`php_runtime.js`) manages worker pool and request queue
- Worker (`php_worker.js`) handles actual PHP execution using php-wasm
- Uses IndexedDB for persistent caching of WASM binary and PHP files
- Implements HTTP simulation with $_SERVER, $_GET, $_POST variables

## Technical Improvements Needed

### 1. Error Handling System
**Current Issue**: PHP errors are returned as plain strings, losing detailed information.

**Current Code**:
```javascript
// php_worker.js line 431
self.postMessage({ id, result: `PHP ERROR: ${err.message}` });
```

**Proposed Solution**:
```javascript
class PhpError extends Error {
  constructor(message, type, code, details = {}) {
    super(message);
    this.type = type; // 'syntax', 'fatal', 'warning', 'timeout'
    this.code = code;
    this.details = details;
    this.timestamp = Date.now();
  }
}

// Usage in worker
self.postMessage({ 
  id, 
  result: null, 
  error: {
    message: err.message,
    type: categorizeError(err.message),
    code: err.code || 0,
    details: { stack: err.stack }
  }
});
```

### 2. Worker Configuration Optimization
**Current Issue**: Default single worker limits parallelism.

**Current Code**:
```javascript
// php_runtime.js line 8
NUM_WORKERS: 1, // Too conservative
```

**Proposed Solution**:
```javascript
// Auto-detect optimal worker count
const getOptimalWorkerCount = () => {
  const cores = navigator.hardwareConcurrency || 2;
  return Math.min(cores, 4); // Cap at 4 to prevent resource exhaustion
};

NUM_WORKERS: getOptimalWorkerCount(),
```

### 3. Input Validation and Sanitization
**Current Issue**: No robust validation of request parameters.

**Current Code**:
```javascript
// php_worker.js line 323
_buildPhpServerEnv({ method, query, payload, headersStr, config = {} })
```

**Proposed Solution**:
```javascript
const validateRequest = ({ method, query, payload, headers }) => {
  const errors = [];
  
  if (!method || !['GET', 'POST', 'PUT', 'DELETE', 'PATCH', 'HEAD', 'OPTIONS'].includes(method.toUpperCase())) {
    errors.push("Invalid HTTP method");
  }
  
  if (!query || typeof query !== 'string') {
    errors.push("Query parameter is required and must be a string");
  }
  
  if (query.includes('..')) {
    errors.push("Directory traversal detected in query");
  }
  
  return errors;
};
```

### 4. Memory Management
**Current Issue**: No explicit memory limits or monitoring.

**Proposed Solution**:
```javascript
class MemoryMonitor {
  constructor(limitMB = 512) {
    this.limitBytes = limitMB * 1024 * 1024;
    this.usage = new Map();
  }
  
  checkWorkerMemory(workerId, phpWeb) {
    const memory = phpWeb.memoryUsage();
    this.usage.set(workerId, memory);
    
    if (memory > this.limitBytes) {
      throw new Error(`Worker ${workerId} exceeded memory limit`);
    }
  }
  
  getTotalUsage() {
    return Array.from(this.usage.values()).reduce((sum, usage) => sum + usage, 0);
  }
}
```

### 5. Rate Limiting
**Current Issue**: No protection against resource abuse.

**Proposed Solution**:
```javascript
class RateLimiter {
  constructor(maxRequestsPerSecond = 10) {
    this.maxRequests = maxRequestsPerSecond;
    this.requests = new Map();
  }
  
  canMakeRequest(clientId) {
    const now = Date.now();
    const windowStart = now - 1000; // 1 second window
    
    if (!this.requests.has(clientId)) {
      this.requests.set(clientId, []);
    }
    
    const clientRequests = this.requests.get(clientId);
    
    // Remove old requests outside the window
    const recentRequests = clientRequests.filter(time => time > windowStart);
    this.requests.set(clientId, recentRequests);
    
    return recentRequests.length < this.maxRequests;
  }
}
```

### 6. Performance Metrics
**Current Issue**: No built-in performance monitoring.

**Proposed Solution**:
```javascript
class PerformanceMetrics {
  constructor() {
    this.metrics = {
      requestCount: 0,
      totalResponseTime: 0,
      averageResponseTime: 0,
      memoryUsage: [],
      workerUtilization: new Map(),
      errorCount: 0
    };
  }
  
  recordRequest(duration, memoryUsed, workerId) {
    this.metrics.requestCount++;
    this.metrics.totalResponseTime += duration;
    this.metrics.averageResponseTime = this.metrics.totalResponseTime / this.metrics.requestCount;
    this.metrics.memoryUsage.push({ timestamp: Date.now(), usage: memoryUsed });
    
    if (!this.metrics.workerUtilization.has(workerId)) {
      this.metrics.workerUtilization.set(workerId, []);
    }
    this.metrics.workerUtilization.get(workerId).push({ timestamp: Date.now(), duration });
  }
  
  getMetrics() {
    return { ...this.metrics };
  }
}
```

### 2. Request Middleware
**Proposed**: Chain of responsibility pattern for request processing.

```javascript
class MiddlewareChain {
  constructor() {
    this.middlewares = [];
  }
  
  use(middleware) {
    this.middlewares.push(middleware);
    return this;
  }
  
  async execute(request) {
    let result = request;
    for (const middleware of this.middlewares) {
      result = await middleware(result);
    }
    return result;
  }
}
```

### 3. Configuration Validation
**Proposed**: Runtime configuration validation.

```javascript
const configSchema = {
  NUM_WORKERS: { type: 'number', min: 1, max: 10 },
  TIMEOUT_WORKER: { type: 'number', min: 1000 },
  DEBUG: { type: 'boolean' },
  DOCUMENT_ROOT: { type: 'string', pattern: /^\/.*$/ },
  SERVER_PORT: { type: 'string', pattern: /^\d+$/ }
};

const validateConfig = (config) => {
  const errors = [];
  for (const [key, value] of Object.entries(config)) {
    const schema = configSchema[key];
    if (schema && !validateValue(value, schema)) {
      errors.push(`Invalid ${key}: ${value}`);
    }
  }
  return errors;
};
```

**Proposed**: Comprehensive sanitization.

```javascript
const sanitizeInput = (input) => {
  if (typeof input !== 'string') return input;
  
  // Remove potential XSS vectors
```
